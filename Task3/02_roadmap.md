# Роадмап трансформации технологического ландшафта «Будущее 2.0»

## Обзор

Роадмап описывает поэтапную трансформацию IT-ландшафта компании «Будущее 2.0» от монолитной архитектуры (DWH на SQL Server 2008) к доменной архитектуре (Data Mesh + Data Lakehouse) с привязкой к бизнес-целям.

**Горизонт планирования:** 12 месяцев
**Промежуточная точка:** 2-3 месяца (архитектура согласована, границы доменов определены)
**Финальная точка:** 12 месяцев (портал самообслуживания работает)
---

### Этап 2.2: Клинический домен и Клинический портал

| Параметр                  | Значение                                   |
|---------------------------|--------------------------------------------|
| **Срок**                  | Месяцы 4-7                                 |
| **Технологии**            | React, Python/FastAPI, PostgreSQL, Redis   |
| **Ответственная команда** | Clinic Domain Team (5-6 разработчиков)     |
| **Ресурсы**               | 2 Backend, 2 Frontend, 1 QA, 1 UX Designer |

**Задачи:**
1. Создание **Клинического портала** (React) — единый веб-интерфейс для врачей и операторов клиник, полная замена PowerBuilder
2. Создание API для управления пациентами и расписанием (FastAPI/Spring Boot)
3. Миграция данных из DWH в PostgreSQL
4. Интеграция с Kafka (события: запись на приём, регистрация пациента)
5. Кэширование расписания в Redis
6. Интеграция Клинического портала с API Gateway (Kong) для маршрутизации к Медицинскому и ИИ-доменам
7. Создание Data Product

**Клинический портал — ключевые функции:**

| Роль         | Функции в портале                                                                                                                                         |
|--------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Врач**     | Просмотр расписания, доступ к медицинским картам (через Медицинский домен), запрос ИИ-анализа снимков (через ИИ-домен), просмотр результатов исследований |
| **Оператор** | Регистрация пациентов, запись на приём, управление очередями, редактирование расписания врачей                                                            |

**Цепочка систем:**
```
Врач/Оператор → Клинический портал (React) → API Gateway (Kong) → Клинический домен (FastAPI + PostgreSQL + Redis)
                                                                 → Медицинский домен (FastAPI + PostgreSQL + S3)
                                                                 → ИИ-домен (FastAPI + MLflow)
```

**Ожидаемые результаты:**
- **Клинический портал** работает как единый интерфейс для врачей и операторов
- Современный веб-интерфейс вместо PowerBuilder
- Онлайн-запись для пациентов
- Мобильный доступ для врачей (адаптивный дизайн)
- Data Product с данными о загрузке клиник

**Влияние на бизнес:**
- **UX** - современный интерфейс вместо PowerBuilder для врачей и операторов
- **Мобильность** - врачи работают с мобильных устройств
- **Онлайн-запись** - привлечение новых пациентов
- **Единый портал** - врач из одного интерфейса видит расписание, медкарты и результаты ИИ-анализа

- Интеграция с внешними банками

**Влияние на бизнес:**
- **Независимость финтеха** - новые продукты за недели
- **Compliance** - соответствие требованиям ЦБ
- **Финансовая аналитика** - данные о выручке и кредитах в реальном времени
