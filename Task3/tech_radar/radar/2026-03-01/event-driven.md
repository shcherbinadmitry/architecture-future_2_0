## Event-Driven Architecture (EDA)

**Статус:** Активно внедряем

**Назначение:** Архитектурный паттерн, в котором компоненты системы взаимодействуют через асинхронные события. Заменяет синхронную интеграцию через ESB.

**Применение:**
- Межсервисное взаимодействие между доменами через Apache Kafka
- Публикация бизнес-событий (пациент принят, услуга оказана, платёж обработан)
- Обеспечение слабой связанности между доменами
- Event sourcing для критичных операций

**Бизнес-сценарии:**
- **Отказоустойчивость** - отказ одного домена не влияет на другие
- **Масштабирование** - асинхронная обработка позволяет обрабатывать пиковые нагрузки
- **Интеграция новых сервисов** - новый сервис подписывается на нужные события без изменений в существующих
- **Аудит** - полная история событий для compliance

**Влияние на бизнес:**
- Доступность системы 99.9%+ (вместо рисков полной остановки при отказе ESB)
- Гарантированная доставка финансовых и медицинских данных
- Возможность replay событий для восстановления после сбоев
