# Анализ проблемных мест текущей архитектуры "Будущее 2.0"

## Выявленные проблемы

| № | Проблема                                         | Описание                                                                                                                           | Затронутые бизнес-сценарии                                                                                                                     | Влияние на бизнес                                                                                                                                                                                           |
|---|--------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | **Монолитное хранилище данных (DWH)**            | Все данные (медицинские, финансовые, операционные, персональные) хранятся в едином SQL Server 2008. Объём данных - сотни терабайт. | • Построение отчётности<br>• Аналитика по всем направлениям<br>• Интеграция новых бизнесов                                                     | • Формирование сложных отчётов занимает часы<br>• Задержки в принятии управленческих решений<br>• Невозможность быстро масштабировать отдельные направления<br>• Риск потери всех данных при отказе системы |
| 2 | **Низкая производительность аналитики**          | Множество трансформаций данных в DWH замедляет аналитические процессы. Отчёты формируются часами.                                  | • Оперативная отчётность для руководства<br>• Анализ эффективности клиник<br>• Финансовая аналитика<br>• Мониторинг KPI                        | • Невозможность принимать решения в реальном времени<br>• Снижение конкурентоспособности<br>• Упущенная выгода из-за несвоевременных решений<br>• Низкая удовлетворённость бизнес-пользователей             |
| 3 | **Связанность бизнес-логики с DWH**              | Значительная часть бизнес-логики реализована внутри DWH. Добавление новых направлений требует изменений в центральном хранилище.   | • Интеграция новых бизнес-направлений<br>• Развитие финтех-сервисов<br>• Расширение ИИ-возможностей<br>• Подключение фармацевтических компаний | • Высокий Time-to-Market для новых продуктов<br>• Риски при изменениях (влияние на все системы)<br>• Невозможность независимого развития доменов<br>• Высокая стоимость изменений                           |
| 4 | **Устаревшие технологии**                        | SQL Server 2008, PowerBuilder - технологии 15+ летней давности. Отсутствие поддержки, сложность найма специалистов.                | • Все операционные процессы<br>• Работа операторов в клиниках<br>• Поддержка и развитие систем                                                 | • Высокие риски безопасности<br>• Отсутствие современных возможностей<br>• Сложность найма и удержания специалистов<br>• Высокая стоимость поддержки legacy                                                 |
| 5 | **ESB как единая точка отказа**                  | Вся интеграция проходит через одну сервисную шину (Apache Camel). При её отказе останавливается весь обмен данными.                | • Обмен медицинскими данными<br>• Финансовые транзакции<br>• Работа ИИ-сервисов<br>• Интеграция с внешними системами                           | • Риск полной остановки бизнеса<br>• Потеря выручки при простое<br>• Репутационные риски<br>• Невозможность обслуживать пациентов                                                                           |
| 6 | **Отсутствие изоляции доменов**                  | Все домены (медицина, финансы, операции) используют общие ресурсы и инфраструктуру.                                                | • Независимое развитие направлений<br>• Масштабирование отдельных сервисов<br>• Управление доступом к данным                                   | • Невозможность масштабировать только нужное направление<br>• Конфликты при развитии разных доменов<br>• Сложность управления доступами<br>• Риски безопасности (нарушение изоляции данных)                 |
| 7 | **Отсутствие self-service аналитики**            | Бизнес-пользователи не могут самостоятельно строить отчёты. Все запросы идут через IT-отдел.                                       | • Оперативная аналитика для бизнеса<br>• Исследовательский анализ данных<br>• Построение кастомных отчётов                                     | • Низкая скорость получения инсайтов<br>• Перегрузка IT-отдела<br>• Упущенные возможности для бизнеса<br>• Низкая data-driven культура                                                                      |
| 8 | **Отсутствие облачной инфраструктуры**           | Вся инфраструктура on-premise. Сложность масштабирования, высокие капитальные затраты.                                             | • Масштабирование под нагрузку<br>• Обеспечение отказоустойчивости<br>• Быстрое развёртывание новых сервисов                                   | • Высокие капитальные затраты<br>• Долгое время развёртывания новых мощностей<br>• Невозможность гибко реагировать на изменения нагрузки<br>• Риски при авариях (отсутствие geo-распределения)              |
| 9 | **Смешение операционных и аналитических данных** | DWH содержит как операционные данные (для работы клиник), так и аналитические.                                                     | • Работа операторов клиник<br>• Построение аналитики<br>• Производительность систем                                                            | • Конкуренция за ресурсы между OLTP и OLAP<br>• Снижение производительности обоих типов нагрузки<br>• Сложность оптимизации                                                                                 |
| 10 | **Отсутствие управления качеством данных**       | Нет единой системы контроля качества, линейности и актуальности данных между доменами.                                             | • Достоверность отчётности<br>• Качество решений на основе данных<br>• Соответствие регуляторным требованиям                                   | • Ошибочные бизнес-решения<br>• Риски регуляторных штрафов<br>• Недоверие к данным<br>• Дублирование данных и несогласованность                                                                             |

## Критичность для бизнес-целей

### Цель 1: Создание масштабируемой "витрины данных" (портал самообслуживания)
**Блокирующие проблемы:**
- №2: Низкая производительность аналитики
- №7: Отсутствие self-service аналитики
- №1: Монолитное хранилище данных

### Цель 2: Независимое развитие бизнес-направлений
**Блокирующие проблемы:**
- №3: Связанность бизнес-логики с DWH
- №6: Отсутствие изоляции доменов
- №1: Монолитное хранилище данных

### Цель 3: Интеграция новых бизнесов (фармацевтика, производство оборудования)
**Блокирующие проблемы:**
- №3: Связанность бизнес-логики с DWH
- №5: ESB как единая точка отказа
- №8: Отсутствие облачной инфраструктуры

### Цель 4: Миграция в облако
**Блокирующие проблемы:**
- №4: Устаревшие технологии
- №8: Отсутствие облачной инфраструктуры
- №1: Монолитное хранилище данных

### Цель 5: Обеспечение безопасности и соответствия регуляторным требованиям
**Блокирующие проблемы:**
- №4: Устаревшие технологии (риски безопасности)
- №6: Отсутствие изоляции доменов
- №10: Отсутствие управления качеством данных
